# Architecture and future security baseline

[DEC-046 and DEC-050 in the PRD](../../prd.md) are accepted. Pure TypeScript domain modules own rotation, phases, coordination, timing and message generation and define ports. They must not import Node APIs, Electron, React or concrete integrations. Integration adapters implement ports alongside domain modules in the utility process. Renderer submits commands and presents snapshots; it cannot directly access adapters. Main owns lifecycle, supervision, IPC routing and safeStorage credential operations; backend integrations own persistence.

DEC-060 accepts enum commands with typed, runtime-validated payloads, backend-owned snapshots and transactional state changes. Publish success and initiate dependent effects only after commit; save failure reports an error without an unsaved operational mode. Keep IPC minimal: no automatic backend-restart or heartbeat framework is added. The [data model](../../data-model-proposal.md) and [IPC contract](ipc-contract.md) specify local types, payloads, replies, credential boundaries and bounded diagnostics. DEC-061 makes #20 design-only closure; executable schema/writer/reload validation moves to the early-development prototype. Verified per-user provider authentication and licensing/deployment constraints remain open. These documents do not prove storage reliability or approve the overall development baseline. JSON is preferred, with SQLite as fallback if unsuitable.

Once paths exist, evaluate ESLint restricted imports or dependency-cruiser rules to enforce inward dependencies and prevent renderer adapter access. Verify enforcement using deliberate forbidden-import cases. Keep domain tests free of simulator, network and platform dependencies.

The future Electron baseline requires context isolation, renderer Node integration disabled, sandboxing where supported, explicit validated IPC channels with sender checks, minimal preload exposure, restrictive Content Security Policy, navigation restrictions and allowlisted external URL handling. Validate commands and responses across privilege boundaries. Main performs secure credential operations through safeStorage; stored credentials must never enter renderer snapshots, logs or exported diagnostics. User-entered keys may exist only as transient input through the dedicated secret command and must be cleared after completion. Validate encryption availability and failure behaviour during detailed design. Review Electron's current security guidance at implementation time; this document does not implement a shell.
